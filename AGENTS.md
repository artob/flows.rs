# Agent guide

## Project map
- Rust 2024 Cargo workspace: `lib/*`. Reusable flow-based programming blocks over
  `async-flow` and Tokio. Run Cargo commands from the repository root.
- `lib/flows` is the feature-gated facade. Block implementations live in
  `flows-{arrow,datafusion,http,json,math,text}`; `flows-derive` implements `#[block]`.
  The other domain crates are scaffolds; inspect source before assuming functionality.
- Root `Cargo.toml` owns shared versions/dependencies and local crate patches.
  `async-flow` uses the registry; `../async-flow` is a reference checkout that may
  differ. Keep edits here; do not search parent directories or silently add a path patch.

## Implementation
- Preserve `#![no_std]` and `#![forbid(unsafe_code)]`. Use `core`/`alloc`; gate
  `std` usage. Transitive Tokio/Arrow dependencies can still require `std`.
- Add blocks in the relevant crate's `src/<operation>.rs`; declare and re-export
  the module in `src/lib.rs`. Follow neighboring signatures: configuration arguments,
  then `async_flow` ports; distinguish single-message `Input`/`Output` from streams.
- `#[block]` preserves the async function and generates `<PascalCase>Block`,
  `new(configuration...)`, model ports, `BlockName`, and `BlockDefinition`.
  It does not generate execution. Expansion currently needs a direct `async-flow`
  dependency, `extern crate alloc`, and `async_flow::Port` in scope for ports.
- Receive with `recv().await?` until `None`; await sends for backpressure.
  Keep channel failures distinct from per-message errors (JSON/HTTP output `Result`s).
  Specify EOF, disconnected-output, empty-input, and null-value behavior.
- Use adjacent `#[tokio::test]` tests with `Channel::bounded`/`oneshot`. Close
  producers and drain bounded outputs concurrently when necessary. Check
  `handle.await??` (join and block errors); existing tests often discard these.
- Feature additions need facade dependency/feature/re-export wiring and optional
  `std` forwarding (`dependency?/std`). The facade disables leaf-crate defaults;
  wire required subfeatures explicitly. Keep runtime dependency defaults off.

## Checks
For Rust changes, replace `flows-text` with the changed crate:

```sh
cargo fmt --all -- --check
cargo test -p flows-text --locked
cargo clippy -p flows-text --all-targets --locked -- -D warnings
cargo check -p flows-text --no-default-features --locked
```

- For macro/shared changes, also run `cargo test --workspace --locked`.
  HTTP's `test_request` contacts public servers; append `-- --skip test_request`
  for offline runs and report the skip.
- Check feature changes on the crate alone and through `flows`; workspace feature
  unification can hide missing flags. The `all` feature differs from `--all-features`.
- Run `cargo test -p <crate> --doc --locked` for rustdoc examples. Report existing
  failures; do not silently refresh dependency resolution to bypass `--locked`.

## Documentation
- Document every new/changed public symbol with rustdoc, including generated APIs.
  Put explanations, contracts, and runnable examples beside the relevant code.
  README additions should be exceptional and demonstrably useful.
- `lib/flows-*/README.md` and `.cargo/packages.{json,md}` are generated by `Rakefile`.
  Edit manifests, `.readme/README.md.j2`, or `lib/*/examples.md.j2` as appropriate;
  regenerate deliberately instead of hand-editing outputs. Generation needs
  Ruby 3.4+, Rake, `tomlrb`, and `minijinja-cli`.
